# Phase 15: Post-Cutover Validation And Cleanup

## Objective

Validate the unified system after production cutover and legacy removal across a complete observation window. Exercise real delivered versions, deterministic security scenarios, protocol current/N-1 combinations, store/updater lag, large images, tainted canvases, Native Messaging cookie scope, rollback readiness, and resource cleanup. Close temporary migration infrastructure only after evidence shows it is no longer needed.

The output of this phase is an auditable validation report, a minimal maintained compatibility matrix, resolved cleanup inventory, and explicit ownership for ongoing operations.

## Non-Goals

- Do not introduce product features or broad refactors during observation.
- Do not remove N-1 compatibility immediately after current reaches all channels.
- Do not delete rollback artifacts, signing verification keys, required SBOM/provenance, licenses, canonical deterministic scenarios, or incident evidence.
- Do not convert live checks into mandatory tests or leak source URLs/cookies into monitoring.
- Do not declare success from aggregate availability alone; each product workflow must be exercised.
- Do not close support/security reports merely to satisfy completion thresholds.

## Dependencies

- Phase 14 completed with a passing deletion gate, clean-tree gate, accepted production rollout, and preserved rollback artifacts.
- Production website, proxy, release downloads, updater channels, Chromium listing, Firefox listing, desktop installers, native host, and CLI are publicly retrievable.
- Monitoring and support channels are operational with privacy-preserving event schemas.
- Previous and current signed artifacts and protocol current/N-1 scenarios remain available.
- Owners and observation duration are recorded in `release/cutover.toml`.
- `crates/fixture-server/`, `crates/xtask/`, `testdata/scenarios/`,
  `crates/dezoomify-job/`, and `packages/protocol-ts/` remain the canonical
  retained paths.

## Sequential Implementation Steps

1. Freeze the post-cutover observation plan. Record start/end UTC, delivered versions/digests by channel, expected N-1 versions, owners, workflow cadence, error/abuse/support thresholds, incident severity definitions, rollback readiness requirements, and minimum sample counts in `artifacts/phase-15/observation-plan.json`.

   **Validate immediately:** cross-check observed artifacts with phase-14 acceptance records and public signature verification. Stop if production points to an unrecorded digest.

2. Add the internal `cargo xtask ci postcutover-snapshot` lane. Collect only coarse, privacy-safe release state: website asset digest/health, proxy policy version, updater metadata digest/channel, public release digests, store-listed versions, protocol capability ranges, and monitoring counters. Redact target/source URLs and accept read-only fixture input for local tests.

   **Validate immediately:** run `cargo xtask ci postcutover-snapshot --state fixtures` and `cargo xtask ci postcutover-snapshot --state production --read-only`. Scan output for credential-bearing URLs, cookie/header values, user IDs, and source targets. This CI lane becomes available only after this step.

3. Add post-cutover deterministic scenarios under
   `testdata/scenarios/post-cutover/`, with routes, payloads, expected transcripts,
   and results co-located. Reproduce release-critical boundaries: direct CORS
   success; ordinary cross-origin image display; visible tainted-canvas assembly,
   controlled `SecurityError`, save guidance, and no product programmatic
   read/process/hash/export attempt; automatic restricted-proxy success only
   after classified CORS/network failure for an eligible public non-credential
   resource; proxy opt-out; visible active transport; credential stripping;
   ineligible-target and SSRF denial; extension
   explicit-action active-tab scan; authenticated privileged direct extension
   origin-clean output with no proxy; native cookie handoff scope; large browser
   rejection/native completion; protocol current/N-1; stale updater; and store
   lag.

   **Validate immediately:** run `cargo xtask test scenario --suite postcutover` and the owning canonical test targets. New scenarios must use fixed content/request expectations and no public network. This scenario suite becomes available only after this step.

4. Add the internal `cargo xtask ci postcutover-validation` lane. Given a release-state snapshot, run installed/package verification and deterministic workflows against versions represented by that state. Emit per-product results and refuse to collapse skipped/unavailable surfaces into success.

   **Validate immediately:** run `cargo xtask ci postcutover-validation --matrix current-current,current-n-1,n-1-current,chromium-delayed,firefox-delayed,updater-paused,website-offline`. This CI lane becomes available only after this step.

5. Schedule `cargo xtask ci postcutover-snapshot --state production --read-only` followed by `cargo xtask ci postcutover-validation` at the agreed cadence. Use protected environments only for read-only API tokens, explicit permissions/timeouts/concurrency, pinned actions, redacted artifacts, and incident thresholds. Keep deterministic validation required; keep low-volume public live compatibility separately classified.

   **Validate immediately:** lint workflow policy and run it against fixture APIs. Prove a fork/PR cannot access production observation credentials.

6. Validate the production website in Chromium, Firefox, and WebKit at each
   checkpoint. Test direct readable export; automatic restricted proxy only
   after classified CORS/network failure for an eligible public non-credential
   target; proxy opt-out; credential-bearing target rejection; visible active
   transport; ordinary image display; visible tainted-canvas assembly with
   `originClean = false`, displayed save guidance, controlled readback
   `SecurityError`, and no product programmatic pixel/process/hash/export attempt;
   CSP/referrer/privacy headers; extension/native escalation; and large-image
   preflight. Verify deployed asset digest before interpreting results.

   **Validate immediately:** compare decoded output pixels, dimensions, MIME, and
   request order with deterministic scenario expectations. Compare exact encoded
   hashes only for the repository-owned deterministic encoder. Confirm no proxy
   request occurs before classified direct failure or while opted out, neither
   proxy hop carries cookies, `Authorization`, browser credentials, or user
   credential headers, and no source
   URL appears in proxy access logs, analytics, page title/history, external-link
   referrer, or uploaded traces.

7. Validate Chromium and Firefox stable/ESR store-delivered extensions. Use clean
   profiles and at least two tabs/two windows. Verify only explicit action starts
   scanning, listeners register before exactly one active-tab reload, finite
   settle/deadline clears listeners, opening/focusing Studio never rearms or
   reloads, browser worker restart is idle, optional permissions behave,
   privileged direct fetch uses the browser session and yields origin-clean
   decoded pixels/dimensions/MIME, and no hosted proxy call occurs. Require exact
   encoded hash only for the repository-owned deterministic encoder.

   **Validate immediately:** collect extension version/ID/permission inventory,
   request transcript, listener cleanup, profile cleanup, decoded output
   pixels/dimensions/MIME, and deterministic-encoder digest when applicable. Any
   store-delivered behavior discrepancy opens a blocking incident for that
   channel.

8. Validate native handoff using store-delivered extensions and installed
   desktop/native host current and N-1 combinations. Website/deep links remain
   untrusted, unsigned, bounded, non-secret, and confirmed. Verify Native
   Messaging browser enforcement of exact allowed extension IDs authenticates
   the sender and that the fresh challenge/nonce binds only the one-use session/
   replay defense rather than authenticating that sender. Test no
   host, current host, N-1 host, incompatible host, consent decline, permission
   denial, matching cookie, unrelated cookie, path escape, redirect escape,
   expiry, cancellation, replay, host crash, and app update during handshake.

   **Validate immediately:** matching authorized job succeeds; all disallowed
   requests have no cookie; consent/scope/memory-only/no-intentional-persistence
   rules hold; owned-buffer overwrite hooks run best-effort; and canary scans find
   no intentional persistence or diagnostic/artifact leakage. Do not claim
   universal zeroization of browser, JavaScript, IPC, allocator, or OS copies.
   All host processes and test registrations clean up.

9. Validate native CLI and desktop on current supported Windows, macOS, and Linux. Cover fresh install, update from N-1, protocol/native-host registration repair, basic output, cache resume, bulk input, cancellation, output collision, large streaming PNG/IIIF, updater offline/stale/tampered metadata, and ownership-safe uninstall in disposable environments.

   **Validate immediately:** compare output hashes, exit/result classes, peak resource bounds, signatures, registration cleanup, and retained user output/settings. Never run uninstall tests against a maintainer's primary installation.

10. Exercise large-image handoff end to end. The website must reject before tile fetch under injected/real safe limits, preserve source state, offer native/manual flow, negotiate current/N-1, complete through native streaming output, and return a non-secret completion status. The extension may solve CORS/auth but must not claim to solve browser memory when capabilities do not.

    **Validate immediately:** request transcript shows zero website tile downloads before handoff; IPC/native messages contain no tile bytes; native output dimensions/hash match; memory remains under recorded bounds.

11. Exercise store and updater lag for the entire observation window. At every observed version change, run `cargo xtask ci postcutover-snapshot --state production --read-only` and `cargo xtask ci postcutover-validation --matrix current-current,current-n-1,n-1-current,chromium-delayed,firefox-delayed,updater-paused`. Keep website offers based on actual published capabilities. Verify users can continue baseline operation while one store remains N-1 or desktop rollout is paused.

    **Validate immediately:** append immutable results to `artifacts/phase-15/lag-timeline.json`. Any baseline current/N-1 failure pauses related promotion and triggers phase-14 rollback procedure.

12. Review privacy/security operations. Inspect proxy abuse/rate-limit reports, CSP violations, updater signature failures, extension permission changes, Native Messaging failures, secret scanner results, dependency advisories, crash reports, and support tickets. Use aggregate/redacted data; do not retrieve user source URLs to diagnose without explicit user-provided consent.

    **Validate immediately:** classify every alert and document owner/status in `artifacts/phase-15/security-review.json`. Unresolved critical/high issues block completion; medium issues require explicit disposition.

13. Run `cargo xtask test live --postcutover --low-volume` at the approved fixed frequency. Test representative formats through products only where source policy permits. Never use live success as a substitute for canonical deterministic scenarios. Convert any reproducible source drift into a sanitized scenario under `testdata/scenarios/` before fixing.

    **Validate immediately:** report source URL only in access-controlled local notes if necessary; committed/uploaded results use format and redacted host/category. Separate transient/source drift from product regression.

14. Build a cleanup inventory. Include temporary preview deployments, rehearsal releases, test updater channels/keys, browser profiles, test store listings/packages where removable, test native-host/protocol registrations, migration-only feature flags, temporary compatibility shims, duplicated artifacts, obsolete CI lanes, local fixture processes, and artifact retention expirations.     **Validate immediately:** automated discovery plus owner review must account for every phase-13/14 temporary resource ID. Store `artifacts/phase-15/cleanup-inventory.json` without credentials.

15. Add the internal `cargo xtask ci postcutover-cleanup-gate` lane. Require observation window completion, all checkpoint workflows, lag matrix, no blocking incidents, rollback readiness, artifact retention confirmation, cleanup inventory, and owner approvals. Reject cleanup of current/N-1 protocol scenarios, rollback releases, licenses, provenance, SBOMs, public keys, deterministic scenarios, or incident evidence.

    **Validate immediately:** run `cargo xtask ci postcutover-cleanup-gate` with an incomplete checkpoint and a protected-item deletion request and require both to fail, then rerun with complete scenario evidence. This CI lane becomes available only after this step.

16. Remove temporary resources in the safest order: stop schedules that create new temporary artifacts; remove preview aliases/deployments; remove test updater metadata while preserving keys/evidence per policy; uninstall test extensions/apps/hosts from disposable profiles/systems; remove isolated registrations; terminate fixture processes; remove migration-only flags/shims explicitly approved by the cleanup gate; then prune expired local artifacts.

    **Validate immediately after each category:** rerun discovery for that resource type and the production smoke relevant to it. Never use wildcard cloud deletion, broad registry deletion, recursive profile deletion outside recorded roots, or repository-wide clean.

17. Re-run `cargo xtask ci`, `cargo xtask release verify`, `cargo xtask ci cutover-clean-tree`, and `cargo xtask ci postcutover-validation --after-cleanup` after cleanup. The post-cutover lane must include installed current/current and current/N-1 smoke, website taint/proxy security, extension cross-browser cleanup, native handoff secret scope, large image, and updater signature checks.

## Deterministic User Workflows

### Delivered Website Taint Workflow

1. Verify production website asset digest against the release manifest.
2. Open deterministic cross-origin taint scenario in Chromium.
3. Prove the unsafe control canvas throws `SecurityError`.
4. Use ordinary image display, verify assembled pixels remain visible and save
   guidance appears, and verify programmatic export is disabled with no product
   read/process/hash/`toBlob`/`toDataURL` attempt.
5. Disable proxy opt-out, start readable acquisition, and verify direct fetch is
   visibly active before the classified CORS/network failure automatically
   selects visible `Restricted proxy` for the eligible target.
6. Compare decoded pixels, dimensions, and MIME, using an exact encoded hash only
   for the repository-owned deterministic encoder, and verify direct attempt,
   classified failure, then proxy request order with no cookies,
   `Authorization`, browser credentials, or user credential headers on either
   proxy hop.
7. Enable proxy opt-out and verify the direct failure occurs with zero proxy
   requests; repeat with a credential-bearing target and verify it is ineligible.
8. Repeat in Firefox and WebKit.

### Store Extension Active-Tab Workflow

1. Install the real store-delivered extension into a clean profile.
2. Open two windows and place noisy fixture in a non-active tab.
3. Click action once on the active image tab.
4. Verify listener registration precedes exactly one active-tab reload, no
   non-active observation occurs, settle/deadline is finite, Studio open/focus
   does not reload or rearm, and zero listeners remain.
5. Export the authenticated scenario through privileged direct browser-session
   fetch and verify origin-clean decoded pixels, dimensions, and MIME; use an
   exact encoded hash only for the repository-owned deterministic encoder.
6. Verify zero hosted proxy requests and remove the disposable profile.

### Native Cookie Scope Workflow

1. Install real desktop/native host and store-delivered extension in a disposable account/profile.
2. Add relevant and unrelated cookie canaries through fixture login.
3. Decline handoff once and verify no secret transfer.
4. Consent with displayed exact origin/path/names/expiry.
5. Complete native output and test sibling/path/redirect/expiry/replay denials.
6. Scan all permitted artifacts/storage/logs and verify zero cookie-value matches.
7. Uninstall and verify ownership-safe registration cleanup.

### Large-Image Handoff

1. Open the large scenario on production website with deterministic safe limit injection.
2. Verify no tile requests and `native required` explanation.
3. Launch installed desktop through a non-secret current protocol link; repeat with the N-1 scenario.
4. Confirm source and output choice, complete streaming output, and verify dimensions/hash/resource bounds.
5. Pause updater in scenario state and prove N-1 still works.

### Cleanup Verification

1. Run `cargo xtask ci postcutover-cleanup-gate`.
2. Execute cleanup only from the approved inventory.
3. Discover residual previews, profiles, registrations, processes, channels, and flags.
4. Run `cargo xtask ci postcutover-validation --after-cleanup`.
5. Verify protected current/N-1 scenarios, rollback artifacts, keys, licenses, SBOMs, provenance, and evidence remain.

## Stop Conditions

- Stop if a production artifact digest/version is unknown or signatures fail.
- Stop if any delivered browser extension observes outside active tab, remains listening, or contacts hosted proxy.
- Stop if tainted-canvas controls no longer prove `SecurityError`, visible
  assembly/save guidance regresses, or product code attempts programmatic
  read/process/hash/export while `originClean` is false.
- Stop if cookie canaries appear outside authorized in-memory browser/native processing.
- Stop if large-image handoff downloads website tiles first or sends tile bytes over IPC.
- Stop if current/N-1 baseline fails during store/updater lag.
- Stop cleanup if observation is incomplete, incidents remain blocking, evidence is missing, or protected artifacts are listed.
- Stop if cleanup changes production health or rollback readiness.
- Stop if source snapshots differ from locked trees or cleanup proposes deleting them without a separate post-migration archive policy.

## Risks And Mitigations

- **Low-frequency delivered regression:** repeated checkpoint workflows using actual store/update artifacts.
- **Store auto-update changes behavior mid-test:** snapshot exact listed/installed version before every run and append lag timeline.
- **Privacy leak in operations:** coarse metrics, redaction scans, access-controlled details, and no source URL telemetry.
- **Premature compatibility removal:** cleanup gate protects N-1 scenarios/adapters and documents retirement separately.
- **Temporary-resource sprawl:** inventory by resource ID/owner/expiry and category-by-category cleanup verification.
- **Cleanup breaks rollback:** preserve previous signed artifacts/deployments/keys and drill read-only readiness afterward.
- **Live source drift confusion:** deterministic tests remain authoritative; classify and fixture reproducible drift.

## Safe Rollback

1. On a production stop condition, follow `docs/rollback-runbook.md` for only the affected website/updater/store surface.
2. Restore prior immutable signed artifacts/configuration; never rebuild under an existing version.
3. Pause cleanup and preserve all evidence/resource identifiers.
4. If a temporary resource was removed too early, recreate only that resource from its recorded immutable config/digest, not from an unreviewed current build.
5. Revert documentation/config/code with targeted patches while preserving unrelated work.
6. Re-run current/N-1 and affected security workflows before resuming.
7. Never hard-reset Git, force-push, broadly clean files, wildcard-delete cloud resources, broadly delete registry keys, or remove primary browser profiles.
